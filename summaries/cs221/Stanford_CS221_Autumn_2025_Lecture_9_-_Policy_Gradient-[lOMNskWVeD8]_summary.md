### 1. Executive Summary & Core Concepts

**Lecture Overview:**
This lecture advances from basic tabular reinforcement learning (RL) algorithms to more sophisticated, scalable approaches. It bridges the gap between discrete state spaces and continuous/high-dimensional inputs by introducing **Function Approximation** (value-based) and **Policy Gradient** methods (policy-based). The core objective is to equip you with the theoretical tools to understand modern "Deep RL" algorithms, explaining how we move from simple lookup tables to parameterized neural networks and how we optimize policies directly by maximizing expected utility.

**Key Concepts Highlight:**
*   **Tabular vs. Function Approximation:** Tabular RL uses a lookup table for every state-action pair, which fails in high-dimensional spaces (e.g., images). Function approximation replaces the table with a parameterized function (like a neural network) to map states/actions to values.
*   **On-Policy vs. Off-Policy:** On-policy algorithms (like SARSA) estimate the value of the policy currently being followed. Off-policy algorithms (like Q-Learning) estimate the value of a target policy (often optimal) using data generated by a different exploration policy.
*   **Bootstrapping:** A technique where the value estimate for the current state is updated using the immediate reward plus the discounted value estimate of the *next* state, rather than waiting for a full rollout to the end.
*   **Policy Gradient Methods:** A class of algorithms that directly optimize the policy parameters ($\theta$) to maximize expected utility, treating the policy as a probabilistic classifier.
*   **REINFORCE Algorithm:** A specific policy gradient algorithm that samples trajectories, calculates the utility of each, and updates the policy weights by weighting the imitation learning loss by the trajectory's utility.
*   **Control Variance (Baselines):** A statistical technique used to reduce the variance of gradient estimates by subtracting a baseline function (often a value estimate) from the reward/utility, provided the baseline does not depend on the action.
*   **Actor-Critic Methods:** A hybrid approach combining policy gradients (the "Actor") with value function estimation (the "Critic") to provide lower-variance, more stable updates.

### 2. Deep Dive: Expanded Lecture Notes

#### 1. Tabular vs. Function Approximation
*   **Detailed Explanation:** In the tabular setting, an RL agent maintains a dictionary where every possible state-action pair has a stored Q-value. This works for small environments (like the "Flaky Tram" MDP). However, in real-world scenarios (robotics, language models), the state space is massive (images, paragraphs). We cannot store a table for every pixel or sentence. Function approximation addresses this by defining $Q(s, a; \theta)$, a function parameterized by $\theta$ (weights of a neural network). Instead of updating a table entry, we update the weights $\theta$ to minimize the error between predicted Q-values and targets.
*   **Context & Nuance:** This concept connects to standard Machine Learning. We treat the RL problem as a regression problem: we map a state-action pair into a feature vector (or directly into a neural network), and we adjust parameters to fit the target values.
*   **Analogy:** Imagine a student learning to drive. In the tabular approach, they have a massive cheat sheet listing every possible road condition and the exact steering input. In function approximation, they learn the *rules* of driving (physics, geometry) and apply those rules to novel situations, rather than memorizing millions of specific scenarios.
*   **Key Takeaway:** Function approximation is necessary for scalability; it replaces discrete memory with generalizable, parameterized models.

#### 2. On-Policy vs. Off-Policy
*   **Detailed Explanation:**
    *   **On-Policy (e.g., SARSA):** The agent estimates the Q-values of the policy it is *currently executing*. The "estimation policy" and the "exploration policy" are the same.
    *   **Off-Policy (e.g., Q-Learning):** The agent estimates the Q-values of a *target* policy (usually the greedy optimal policy) while exploring using a different policy (e.g., $\epsilon$-greedy).
*   **Context & Nuance:** The distinction matters for data efficiency. Off-policy allows an agent to learn from random or suboptimal exploration data while still converging on the optimal policy. SARSA requires the exploration policy to be close to optimal, otherwise, it estimates the value of a bad policy.
*   **Analogy:** **On-Policy** is like a chef tasting their own dish while cooking to adjust the recipe. **Off-Policy** is like a chef using a recipe card (target policy) to judge the dish, even if they are currently experimenting with weird ingredients (exploration policy).
*   **Key Takeaway:** Off-policy learning is generally more flexible because it decouples the data generation process from the policy being evaluated.

#### 3. Bootstrapping
*   **Detailed Explanation:** Bootstrapping is the recursive step in value-based RL. Instead of waiting for a full rollout to calculate total utility, the agent updates its estimate using: $Q(s,a) \leftarrow Q(s,a) + \alpha [r + \gamma Q(s', a') - Q(s,a)]$. It uses its *current* estimate of the next state's value to update the current state's value.
*   **Context & Nuance:** This contrasts with Monte Carlo methods, which wait for the full trajectory to finish. Bootstrapping allows for immediate updates but introduces a dependency on the accuracy of subsequent Q-estimates.
*   **Analogy:** If you are hiking and need to estimate the total time to the summit, bootstrapping is saying, "I know it took 1 hour to get here, and I estimate the rest of the trail will take 2 hours based on my current speed." Monte Carlo is waiting until you actually reach the summit to say, "It took 3 hours total."
*   **Key Takeaway:** Bootstrapping enables real-time learning by leveraging current estimates of future value, rather than waiting for ground-truth outcomes.

#### 4. Policy Gradient Methods (The Direct Approach)
*   **Detailed Explanation:** Value-based methods estimate $Q(s,a)$ and derive the policy by taking the argmax. Policy-based methods skip the Q-function entirely and directly parameterize the policy $\pi_\theta(a|s)$ as a probabilistic classifier. The goal is to maximize $V(\theta) = \sum_{\tau} P(\tau) U(\tau)$, the expected utility of trajectories.
*   **Context & Nuance:** This is the "state of the art" approach in modern RL. It treats the policy as a classifier where the input is the state and the output is a distribution over actions. We optimize this distribution to maximize reward.
*   **Analogy:** In value-based, you are calculating the score for every move and picking the highest. In policy-based, you are training a brain that *knows* how to move well, adjusting its internal logic directly based on success/failure.
*   **Key Takeaway:** Policy gradients allow us to optimize stochastic policies directly, which is crucial for environments where randomness is inherent (e.g., robotics).

#### 5. The REINFORCE Algorithm
*   **Detailed Explanation:** REINFORCE is the foundational policy gradient algorithm. It works by:
    1.  Sampling a trajectory $\tau$ using the current policy.
    2.  Calculating the utility $U(\tau)$ (discounted sum of rewards).
    3.  Updating the policy parameters by taking the gradient of the log-probability of the trajectory, weighted by the utility.
    Essentially, it performs "weighted imitation learning": if a trajectory had high utility, the algorithm reinforces the actions taken in that trajectory; if low/negative, it suppresses them.
*   **Context & Nuance:** REINFORCE is "on-policy" because it samples from the current policy. It is a "first-order" method because it relies on the immediate gradient of the sampled path.
*   **Analogy:** It is like a student who takes a test (rollout), gets a grade (utility), and then reviews their work. If they got a high score, they study harder on the specific questions they got right. If they got a low score, they ignore those specific questions.
*   **Key Takeaway:** REINFORCE simplifies RL to a form of supervised learning where the "labels" are weighted by the total reward of the episode.

#### 6. Control Variance & Baselines
*   **Detailed Explanation:** In REINFORCE, the gradient estimate can have high variance, leading to slow convergence. We can reduce this variance by subtracting a **baseline** $b(s)$ from the utility. The key identity is that $E[\nab_\theta \log \pi_\theta(\tau) b(s)] = 0$ for any baseline $b(s)$ that does not depend on the action $a$. This means subtracting $b(s)$ does not change the *mean* of the gradient estimate (it remains unbiased) but can drastically reduce the *variance*.
*   **Context & Nuance:** This connects to statistics. If you know the average score of a class is 70, and you want to measure a student's performance, subtracting 70 from their score helps normalize the data. In RL, we often use a learned value function (like a Critic) as this baseline.
*   **Analogy:** Imagine measuring the height of a mountain. If you measure from sea level, your numbers are huge and noisy. If you measure from the local base camp (a baseline), your measurements are smaller and more precise relative to the peak you care about.
*   **Key Takeaway:** Baselines are a mathematical trick to stabilize training by removing the "noise" of absolute reward values, focusing updates on relative performance.

#### 7. Actor-Critic Methods
*   **Detailed Explanation:** This combines the "Actor" (the policy network that chooses actions) and the "Critic" (a value network that estimates the utility/value of states). The Critic provides the baseline for the Actor. This reduces variance compared to pure REINFORCE, at the cost of introducing some bias (because the Critic's estimate is an approximation).
*   **Context & Nuance:** This is where Deep RL truly lives. The Actor and Critic can be separate networks or even share parameters. The Critic "critiques" the Actor's performance, providing a stable signal for the Actor to update against.
*   **Analogy:** A pilot (Actor) and a co-pilot (Critic). The pilot flies the plane. The co-pilot monitors the instruments and says, "We are on track" or "We are drifting left." The pilot adjusts based on the co-pilot's feedback, rather than just guessing.
*   **Key Takeaway:** Actor-Critic methods trade a small amount of bias for a significant reduction in variance, leading to faster and more stable convergence in complex environments.

**Answer Key & Explanations**

1.  **Tabular vs. Function Approximation:** Tabular uses a lookup table (dictionary) for every state-action pair, which is limited by memory and only works for small, discrete states. Function approximation uses a parameterized function (like a neural network) to map high-dimensional inputs (images, text) to values, allowing generalization to unseen states.
2.  **On-Policy vs. Off-Policy:** On-policy (SARSA) estimates the value of the policy currently being followed. Off-policy (Q-Learning) estimates the value of a target policy (usually optimal) using data from a different exploration policy.
3.  **Bootstrapping:** It is the process of updating a value estimate using the immediate reward plus the discounted value estimate of the *next* state, rather than waiting for the episode to end. It allows for incremental updates.
4.  **$\theta$ in Policy Gradients:** $\theta$ represents the parameters of the policy network (the weights of the classifier) that map states to a probability distribution over actions.
5.  **Objective Function:** The objective is to maximize the **expected utility** of a trajectory, $V(\theta) = \sum P(\tau) U(\tau)$.
6.  **Robot Arm/Image State:** A lookup table is impossible because the state space (all possible images) is too large to store. We must use **function approximation** (a neural network) to process the image input and output a Q-value or action probability.
7.  **REINFORCE & Utility:** The utility acts as a weight for the gradient update. If utility is negative, the algorithm decreases the probability of the actions taken in that trajectory (suppressing them). If positive, it increases the probability (reinforcing them).
8.  **Variance Reduction:** You should use **Control Variance** (Baselines). By subtracting a baseline function $b(s)$ (often a learned value estimate) from the utility, you reduce the variance of the gradient estimate without introducing bias.
9.  **SARSA vs. Q-Learning:** Q-Learning is better for estimating the *optimal* policy with random exploration because it is off-policy. It aims to estimate $Q^*$ (optimal value) regardless of the exploration noise. SARSA would estimate the value of the *random* policy, which is not optimal.
10. **Utility Calculation:** Walk (-1) + Walk (-1) + Tram (-2) = **-4** (assuming $\gamma=1$).
11. **Critique of Convergence:** In simple linear MDPs, tabular methods have strong convergence guarantees. Non-linear function approximation (deep nets) can suffer from local minima, instability, and overfitting to specific exploration patterns, meaning the agent might get stuck in suboptimal policies that look good locally but fail globally.
12. **REINFORCE as Weighted Imitation:** This reframes RL as a supervised learning problem where the "labels" are the actions taken, but the "confidence" or "weight" of each training example is determined by the total reward. It implies that exploration is just generating data, and the "learning" is filtering that data based on success.
13. **Baseline Independence:** If $b(s)$ depended on the action $a$, the gradient of $\log \pi(a|s)$ with respect to $\theta$ would no longer sum to zero. This would introduce **bias** into the gradient estimator, causing the agent to systematically move away from the true optimal policy. The independence ensures the baseline only shifts the "center" of the reward distribution without skewing the learning direction.
